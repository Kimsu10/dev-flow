# 카테고리 추가와 AI 조사 초안

## 사용 흐름

관리자 글쓰기 권한, CodeMirror Markdown 편집기, 기존 미리보기 및 발행 절차를 유지합니다. 직접 작성을 기본으로 하며 AI 패널을 열거나 조사에 실패해도 현재 본문은 변경되지 않습니다.

1. 카테고리 선택 옆 **+ 카테고리 추가**에서 이름을 입력하고 **저장 후 선택**을 누르면 현재 글에 바로 선택됩니다. 같은 이름의 기존 항목이 있으면 재사용합니다.
2. **AI 글 작성**을 누르면 질문이 AI 서비스에 전달되고 발행 시 공개된다는 안내가 나타납니다. 확인 체크 후 질문을 제출합니다.
3. AI가 웹 자료를 검색한 초안과 출처를 별도 미리보기에 제시합니다. **편집기에 적용**을 눌러야 본문이 교체됩니다. 제목, 카테고리 등 다른 필드는 유지합니다.
4. 적용 후에는 기존 편집기에서 내용을 수정합니다. 원래 질문과 출처는 브라우저 임시저장, 복원, 서버 저장 및 다시 열기에서 유지됩니다.
5. 공개 글의 제목 위에 AI 안내와 원래 질문, 본문 아래에 출처 링크를 표시합니다. 직접 작성한 글과 기존 글에는 이 표시가 없습니다. 미발행 글의 질문·출처는 공개 API로 조회할 수 없습니다.

## 책임과 데이터

- `CategoryInput.vue`: 이름 입력·추가·선택. 서버 항목을 ID 기준으로 합쳐 화면 중복을 방지합니다.
- `AiDraftPanel.vue`: 공개 안내, 조사 요청, 출처와 기존 `MarkdownPreview`를 이용한 미리보기, 명시적인 적용 이벤트.
- `PostCreateView.vue`: 기존 편집기 연결 및 저장·복원, 적용한 초안과 글의 연관 관계 관리.
- `AiSources.vue`: 편집·미리보기·공개 글에서 같은 출처 목록을 표시합니다. HTTP(S) 이외의 주소는 링크로 렌더링하지 않습니다.
- API는 기존 Controller → Service → Mapper 구조를 유지합니다. 신규 변경 API는 `/api/admin/**`에 있어 기존 관리자 인증과 CSRF가 적용됩니다. 일반 사용자와 Agent는 이 관리 기능을 호출할 수 없습니다.
- 조사 결과는 `blog.ai_drafts`에 원래 질문·출처·원본 Markdown으로 보관합니다. 생성만으로 글을 만들거나 발행하지 않습니다. 글은 저장 요청의 `aiDraftId`로 연결하며 질문·출처를 클라이언트가 임의로 제출하지 않습니다.
- 기존 업데이트 API가 `aiDraftId`를 생략하거나 null로 보내도 이미 적용된 원본 정보는 지우지 않습니다. 다른 초안을 명시적으로 적용하면 연결을 교체합니다. 새 직접 작성 글은 null입니다.

## PostgreSQL 마이그레이션

`V5__category_identity_and_ai_drafts.sql`:

- 카테고리 이름의 앞뒤 공백, 중간 공백, 대소문자를 비교 키로 정규화하는 함수와 고유 인덱스를 추가합니다.
- `INSERT ... ON CONFLICT ... RETURNING`으로 동시에 같은 이름을 추가해도 하나만 생성하고 같은 ID를 반환합니다.
- 기존 카테고리 ID·글 연결을 변경하지 않습니다. 이전 데이터에 정규화 후 중복 이름이 있다면 마이그레이션은 실패하며 자동으로 항목을 삭제·병합하지 않습니다. 먼저 충돌을 점검하고 기존 참조를 고려해 정리해야 합니다.
- AI 초안 테이블과 글의 nullable FK를 추가합니다. 기존 글에는 AI 정보가 연결되지 않습니다.

## AI 설정

새 라이브러리 없이 Java 21 HTTP 클라이언트와 Spring RestClient로 OpenAI Responses API의 `web_search`를 사용합니다. 구성은 [공식 웹 검색 문서](https://developers.openai.com/api/docs/guides/tools-web-search?api-mode=responses)와 [API 시작 안내](https://developers.openai.com/api/docs/quickstart)를 기준으로 했습니다.

루트 `.env`에 서버 전용 설정을 추가합니다. 실제 키는 커밋하거나 프런트의 `VITE_*` 변수에 넣지 않습니다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-6.2-astra
```

`scripts/start-backend.ps1`은 이 두 설정도 읽습니다. IntelliJ 실행 시에는 백엔드 실행 설정의 환경변수로 전달해야 합니다. 모델에는 웹 검색을 지원하고 해당 계정에서 사용 가능한 모델을 설정합니다.

- 외부 요청은 웹 검색 도구를 필수로 사용하도록 설정하고 `store: false`를 보냅니다.
- 공급자 응답에 완료된 웹 검색, 완료된 답변, 유효한 URL 인용이 있어야 초안으로 채택합니다. 모델이 본문에 쓴 임의 URL만으로 출처를 만들지 않습니다.
- API 키 누락은 `503 AI_NOT_CONFIGURED`, 공급자 오류는 `502 AI_UNAVAILABLE`, 미완성·미조사·출처 없는 결과는 `502 AI_UNVERIFIED`로 알립니다. 샘플 글로 대체하지 않습니다.
- 서버의 동시 조사 수는 프로세스당 최대 2개이며 자동 재시도로 요청을 늘리지 않습니다. 연결 10초·응답 100초, UI 120초 제한을 둡니다. 외부 조사 중 DB 트랜잭션을 열어 두지 않습니다.
- 공급자 응답 본문과 인증 헤더, 키 및 원래 질문은 로그에 기록하지 않습니다. 질문과 출처는 기능상 DB·로컬 임시저장에 보관되며 발행 후 공개됩니다.
- 실제 자료 검색은 사실 정확성을 보증하지 않습니다. 작성자가 원문과 초안을 확인하고 편집한 뒤 발행해야 합니다.

## 검증 범위 (2026-11-20)

- 프런트: 기존 네이티브 파일 잠금을 피하기 위한 `artifacts/blog-veta-frontend`의 동일 소스·잠금 파일로 `npm ci`, `npm test`, `npm run build` 실행. 테스트 60개 통과, TypeScript 및 프로덕션 빌드 성공.
- 백엔드: Java 21에서 `gradlew.bat build postgresTest --no-daemon` 실행. 일반 테스트 21개, 실제 PostgreSQL 테스트 23개 통과. 별도 스레드·트랜잭션의 카테고리 동시 생성과 실제 SQL 고유 제약, 관리자/CSRF 경계, 조사만 했을 때 미공개, 적용·수정·발행 후 질문·출처 보존을 확인했습니다. 테스트 글·계정은 롤백, 동시 생성 테스트만 해당 UUID 이름의 fixture를 삭제합니다.
- 공급자 계약 테스트: HTTP 모의 전송으로 Responses API 요청 형식, 웹 검색 강제, 공급자 URL 인용 추출, 미조사·미완성·위험 URL 거부, 오류 본문 비노출을 확인했습니다. API 키 미설정의 503 동작도 검증합니다.
- 실제 Chromium: `node scripts/verify-authoring-ui.mjs`로 1440px 데스크톱·390px 모바일에서 기존 CodeMirror 편집, 카테고리 선택, 조사 전 공개 안내/동의, 미리보기만으로 본문 미변경, 명시적 적용, 편집·복원·다시 열기·공개 표시를 확인했습니다. 이 UI 검증은 명시적인 모의 API fixture이며 실제 AI 또는 DB 호출 검증을 대신하지 않습니다. JS 오류·가로 넘침 없음.
- 브라우저 결과·스크린샷: `artifacts/authoring-ui/1795102123953/`.
- **실제 외부 AI 연동은 미검증**: 로컬 `.env`와 실행 환경에 `OPENAI_API_KEY`가 없어 유료 외부 요청을 보내지 않았습니다. 실제 계정의 모델 사용 가능 여부, 지연 시간 및 조사 결과 품질은 키를 설정한 뒤 확인해야 합니다.
- Docker CLI를 사용할 수 없어 Compose 재기동 검증은 하지 않았습니다. H2만으로 대체하지 않고 실행 중인 실제 로컬 PostgreSQL에 연결했습니다.

스테이징·커밋·푸시는 수행하지 않습니다.

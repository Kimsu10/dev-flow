# 이미지 첨부와 S3 저장

관리자 글쓰기의 파일 선택, 드래그&드롭, 이미지 붙여넣기를 지원한다. 이미지당 5MB, 한 저장 요청당 10개·총 25MB까지 PNG/JPEG/GIF/WebP를 허용하며 서버에서도 실제 파일 헤더와 MIME을 확인한다. SVG는 허용하지 않는다.

## 저장 순서

1. 첨부 직후 파일은 사용자별 브라우저 IndexedDB에 임시 보관한다. 편집기에는 임시 식별자를 넣고 미리보기에서만 로컬 이미지를 표시한다. 이때 서버와 S3에는 전송하지 않는다.
2. 로컬 임시저장은 본문의 임시 이미지 식별자를 보관한다. 같은 브라우저·계정에서는 파일도 복원한다. 브라우저 데이터를 지우거나 다른 기기에서 복원하면 다시 첨부해야 한다.
3. 저장 버튼을 누르면 아직 본문에서 사용하는 이미지와 글 정보를 `multipart/form-data`로 함께 보낸다. 제거한 이미지는 업로드하지 않는다.
4. 서버는 기존 권한·수정 버전을 검증하고 DB 트랜잭션 안에서 글을 저장한 뒤 S3에 파일을 올린다. 본문의 임시 주소를 `/api/posts/{postId}/images/{imageId}`로 바꾸고 DB에 이미지 메타데이터를 저장한다.
5. 성공하면 브라우저의 업로드 완료 파일을 정리한다. 실패하면 글 변경을 롤백하고 업로드가 완료된 이번 요청의 파일을 삭제한다. 기존 글의 이미지와 S3 객체는 건드리지 않는다.

DB와 S3는 분산 트랜잭션이 아니다. 프로세스 강제 종료, S3 업로드 결과를 알 수 없는 네트워크 단절, 롤백 삭제 권한 오류에는 고아 객체가 남을 수 있다. 정리 실패는 비밀값 없는 경고로 남기므로 운영에서는 별도의 대조 정리 작업을 고려한다. 글 삭제는 기존대로 소프트 삭제이며 이미지 읽기를 차단한다. 기존 첨부를 본문에서 제거해도 과거 S3 객체를 자동 삭제하지 않는다.

## 경로와 이름

```text
2026/Spring Boot/11/Spring Boot_20261127153045123.png
```

- 경로의 연·월은 **글 최초 생성 시각의 한국 시간**이다. 게시 일시를 과거나 미래로 지정해도 생성 기준 경로를 사용한다.
- 카테고리는 저장 시 선택된 이름을 사용한다. 미선택 시 `미분류`; 경로 구분자 등은 `_`로 치환하고 길이를 제한한다.
- 파일명은 `카테고리_업로드연월일시분초밀리초.확장자`다. 프로세스 내 시간값을 단조 증가시키고 S3 `If-None-Match: *` 조건으로 기존 파일 덮어쓰기를 막는다. 다른 서버와 이름이 충돌하면 저장 실패로 처리하므로 다시 저장하면 된다.
- 수정 시 **새로 첨부하는 파일만** 당시 카테고리 경로로 저장한다. 기존 이미지는 이동하지 않는다.

## AWS 설정

백엔드 프로세스에 `S3_BUCKET_NAME`, `AWS_REGION`을 전달하고 SDK 기본 자격 증명 체인(예: `AWS_PROFILE=devflow-dev`, 환경변수, 배포 환경 IAM 역할)을 사용한다. `.env`는 IntelliJ에 자동 주입되지 않으므로 실행 구성에서 연결하거나 `scripts/start-backend.ps1`을 사용한다. AWS 비밀키는 프런트 코드나 VITE 변수에 넣지 않는다.

`aws login --profile devflow-dev`로 만든 `login_session` 프로필도 지원하도록 SDK `signin` 모듈을 포함한다. 로컬 로그인 세션이 만료되었다면 같은 프로필로 다시 로그인한다. [AWS Java console login credentials](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials-temporary.html).

버킷은 비공개로 유지하고 Block Public Access를 켠다. 서버 역할에는 해당 버킷 객체에 대한 `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` 권한이 필요하다. SSE-KMS를 사용한다면 해당 키 정책과 KMS 권한도 별도로 맞춘다. 서버가 S3에 직접 접근하므로 브라우저용 버킷 CORS나 공개 ACL은 필요하지 않다.

이미지는 동일 출처 API를 통해 제공한다. 공개 완료 글은 독자가 볼 수 있고, 비공개 글은 작성자만, 미발행·예약 공개 글은 기존 관리자 읽기 정책에 따라 조회한다. 이미지 응답은 `no-store`로 처리하여 공개 범위 변경 후 브라우저 캐시가 남지 않게 한다.

조건부 쓰기 참고: [AWS S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html).

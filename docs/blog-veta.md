# 블로그 독자 경험 개선

## 게시글 검색

`GET /api/posts`에 선택 파라미터 `q`를 추가했습니다. 제목, 요약, Markdown 본문에서 대소문자를 구분하지 않는 부분 문자열 검색을 수행합니다. 앞뒤 공백을 제거하며 검색어는 최대 100자입니다. 빈 검색어는 기존 목록과 동일합니다.

- 기존 `categoryId`, `page`, `size`와 함께 사용할 수 있습니다.
- 발행 시각이 지난 공개 글만 검색합니다. 초안, 삭제 글, 미래 발행 글은 제외됩니다.
- `%`, `_`, `!`는 일반 문자로 검색합니다. SQL 파라미터 바인딩을 사용합니다.
- 검색 결과 수와 목록은 동일한 조건을 적용합니다.
- 검색어와 카테고리는 URL에 남습니다. 검색 제출 및 카테고리 변경 시 페이지를 초기화합니다.
- 새 의존성이나 DB 마이그레이션은 없습니다. 현재 규모에서는 PostgreSQL `ILIKE`를 사용하며, 데이터가 커지면 실제 실행 계획을 바탕으로 검색 인덱스를 검토해야 합니다.

## 검증 환경

기존 `frontend/node_modules`의 네이티브 바이너리가 사용 중이라 `npm ci`가 EPERM으로 실패했습니다. 실행 중인 프로세스를 종료하지 않고, 무시되는 `artifacts/blog-veta-frontend`에 소스와 잠금 파일을 복사하여 `npm ci`, `npm test`, `npm run build`를 실행합니다.

Gradle은 기존 Java 21과 사용자 Gradle 캐시를 사용합니다. 로컬 PostgreSQL에 대해 기존 롤백 방식의 `postgresTest`를 실행합니다. Docker CLI는 이 환경에서 찾지 못했으므로 Docker Compose 환경 자체의 검증과는 구분합니다.

# 게시 일시와 공개 범위

## 저장과 수정

- 기존 Markdown 편집기, 관리자 글쓰기 권한 및 AI 초안 흐름을 유지합니다.
- 저장 버튼 옆에 게시 일시와 공개/비공개 선택을 배치했습니다. 새 글의 기본은 비공개이며, 선택한 범위로 한 번에 저장합니다. AI 초안 적용 여부와 관계없이 같은 API를 사용합니다.
- 게시 일시는 기기 현지 시각으로 입력하며 서버에는 시간대가 포함된 ISO 시각으로 전달합니다. 새 글에서 생략하면 DB의 저장 트랜잭션 시각을 사용합니다.
- 수정 시 생략하거나 입력란을 비우면 기존 게시 일시를 유지합니다. 날짜를 새로 입력하면 변경할 수 있습니다. 생성 시각은 수정하지 않습니다.
- 입력란은 분 단위로 표시하되, 기존 날짜를 건드리지 않은 수정 요청에서는 날짜를 보내지 않아 원래 DB 값의 초·마이크로초까지 보존합니다.
- 목록·검색·홈·관련 글 및 내 글은 게시 일시 기준으로 정렬합니다. 상세 화면 역시 기존 `publishedAt`를 기준으로 표시합니다. 미래 게시 일시의 공개 글은 기존 정책대로 지정 시각부터 공개 조회됩니다.
- 브라우저 임시저장에 게시 일시와 공개 범위를 포함하고 복원합니다. 서버 재편집 시에도 기존 선택값을 불러옵니다.

## 비공개 권한

- 공개 범위(`visibility`)와 기존 초안/검토/발행 상태(`status`)는 별도입니다. 새 편집기의 저장은 완료 상태로 저장하며 PUBLIC/PRIVATE가 실제 공개 여부를 결정합니다. 기존 API가 공개 범위를 생략하면 기존 초안·검토·발행 절차를 유지합니다.
- 비공개 글은 작성자만 본문과 관리 정보를 조회·수정·삭제·공개 전환할 수 있습니다. 다른 관리자에게도 404를 반환합니다. 기존 공개 글에 대한 관리자 권한은 유지합니다.
- 공개 목록, 검색 결과, 건수, 홈, 관련 글 및 공개 게시글 통계 쿼리에서 비공개 글을 제외합니다. 관리자 목록도 다른 작성자의 비공개 글을 제외합니다.
- 공개 직접 URL은 작성자에게만 비공개 본문을 반환하고 익명·다른 사용자·다른 관리자에게는 404를 반환합니다. 응답은 `private, no-store`로 브라우저 캐시의 오래된 공개 응답 재사용을 방지합니다.
- 비공개 상세는 방문 통계를 전송하지 않습니다. 서버 방문 수집도 공개 글만 허용합니다. 개별 글 통계 URL 역시 작성자 검사를 거칩니다.
- AI 초안 원래 질문/출처 관리 URL은 생성 작성자, 연결된 글의 작성자 또는 이미 공개된 글의 자료에 대해서만 접근을 허용합니다. 공개 전환 시 기존 AI 안내·질문·출처가 같이 표시됩니다.
- 내 글(`/my-posts`, 관리자 전용)은 본인이 작성한 글만 표시하고 비공개 배지, 재편집, 공개 전환을 제공합니다. 공개 전환은 버전 검사를 적용하고 게시 일시를 초기화하지 않습니다.

## 마이그레이션과 호환

`V6__post_visibility.sql`은 PUBLIC 기본값의 열과 작성자/게시 일시 인덱스만 추가합니다. 기존 글의 상태, 날짜, 작성자 및 AI 연결을 일괄 변경하지 않습니다.

기존 API의 발행/발행 취소도 기존 게시 일시를 지우거나 현재 시각으로 덮어쓰지 않습니다. 공개 범위를 생략한 수정 요청은 기존 범위를 유지합니다. 기존 작성자 없는 글을 관리자가 명시적으로 비공개 전환할 때에만 해당 관리자를 작성자로 지정해 접근 불능 글이 생기지 않도록 합니다. 다른 작성자의 공개 글을 임의로 비공개 전환해 소유권을 바꿀 수는 없습니다.

## 검증 범위

- 프런트: `npm ci`, `npm test`, `npm run build` 성공. 기존 네이티브 바이너리 잠금 문제를 피하기 위해 무시되는 `artifacts/blog-veta-frontend`의 동일 소스·잠금 파일로 검증했습니다. 11개 파일, 63개 테스트 통과.
- 백엔드: Java 21 `gradlew.bat build postgresTest --no-daemon` 성공. 일반 테스트 21개, 실제 로컬 PostgreSQL 테스트 27개 통과.
- 신규 실제 PostgreSQL 검증: 저장 시각 기본값, 기존 날짜·생성 시각 보존, 게시 일시 변경, 일시 순 정렬, 비공개 목록·검색·건수·관련 글 제외, 비공개→공개→비공개 전환 전후 익명/일반 사용자/다른 관리자 404와 작성자 접근, AI 질문/출처 접근, 내 글 및 공개 전환 시 날짜 보존. 테스트 데이터는 롤백합니다.
- 초기 회귀에서 Java 시계로 기본 게시 일시를 지정하면 DB 트랜잭션 시각보다 미래로 판정될 수 있음을 확인해, 기본 일시는 DB에서 지정하도록 수정했습니다. 최종 전체 테스트는 모두 통과했습니다.
- 브라우저: 실제 Chromium/CodeMirror에서 1440px 데스크톱·390px 모바일의 일시/공개 범위 입력, 비공개 저장, 임시저장·복원, 내 글의 공개 전환, 재편집 및 공개 AI 표시를 확인했습니다. 브라우저 API는 모의 fixture로 외부 AI 또는 실제 DB 테스트를 대체하지 않습니다.
- 최종 브라우저 결과와 스크린샷: `artifacts/authoring-ui/1795104803633/`.
- Docker CLI가 없어 Compose 재기동은 미검증입니다. 실제 실행 중인 로컬 PostgreSQL에 연결해 검증했습니다.
- 실제 외부 AI 호출은 `OPENAI_API_KEY`가 없어 미검증입니다. 이번 변경의 AI 저장·권한 테스트는 합성 AI 응답과 실제 PostgreSQL을 결합했습니다.
- Git 스테이징·커밋·푸시·원격 변경 및 운영 배포는 수행하지 않았습니다.

## 후속 Git 반영 검증 (2026-11-21)

이후 사용자가 스테이징·커밋·일반 push를 별도로 승인하여 기능별 커밋으로 정리했습니다. 프런트의 잠금 파일 기반 설치, 테스트 63개 및 빌드는 다시 통과했습니다. 백엔드 일반 테스트 21개도 캐시를 우회해 재실행하여 통과했습니다.

이 시점의 실제 PostgreSQL 재실행은 로컬 DB 포트가 닫혀 있어 연결 거부로 실패했습니다. 위의 실제 PostgreSQL 27개 통과는 2026-11-20 구현 완료 시점의 결과이며, 현재 DB 상태에서 재확인한 결과로 해석하면 안 됩니다. DB를 다시 실행한 뒤 `gradlew.bat postgresTest --rerun-tasks --no-daemon`으로 재확인할 수 있습니다. Docker CLI도 찾을 수 없어 컨테이너를 임의로 재시작하지 않았습니다. 운영 배포는 하지 않았습니다.
